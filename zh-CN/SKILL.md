# 数学研究流程

## 1. 入口与项目布局

执行流程前，阅读适用于目标项目的指令。
用户要求开展研究或续做研究时，使用本流程。
禁止仅因用户编辑这些指令就开始研究。
项目规则规定角色、准入、预算和结果含义。
阅读所分配角色的章节和必要任务记录。

全部持久路径以项目根目录为基准。
日期使用用户所在时区。
项目默认时区为 `Asia/Shanghai`。
在整个项目内连续编号轮次。
轮次跨日继续时，保留名称中的创建日期。

文件树表示允许的保存位置。到达必要研究阶段时才创建文件。
`R003`、`R003P01`、`L001` 和日期均为示例。

```text
project/
  README.md
  CURRENT.yaml
  additional_papers/
  rounds/
    yyyy_mm_dd_roundNNN/
      PROBLEM.md
      ROUND.yaml
      ROUTES.md
      CHECKPOINT.yaml
      code/R003P01/
        work/
        runs/E001/                  # RUN.yaml、固定代码、输入和输出
      audit/
        EVENTS.jsonl
        recovery/RECOVERY_001.md    # 用于详细恢复记录
      fact_graph/
        HEAD.yaml
        snapshots/R003_G0000.json
      src/                         # main.tex、references.bib、CLAIMS.yaml
      out/                         # paper.pdf、BUILD.yaml
      research_papers/
        RESEARCH.md
        SOURCES.yaml
        pdf/L001__short-title.pdf
      pairs/R003P01__route-name/
        TASK.md
        drafts/
        submissions/v01/SUBMISSION.md
        reviews/v01/REVIEW.md
      final/
        START_HERE.md
        RESULT.yaml
        PROBLEM.md
        FACTS.json
        FRONTIER.md
      temp/
```

保留这 9 类轮次目录的职责。
空目录可建可不建。
禁止创建空证明、空审核、空 PDF 或尚未发生的提交版本。

使用稳定标识，例如：

| 对象 | 示例 |
| --- | --- |
| 目标与修订版本 | `T001@r1` |
| 逻辑配对 | `R003P01` |
| 路线 | `ROUTE00301` |
| 正式提交 | `R003P01/v02` |
| 事实与修订版本 | `F0042@r1` |
| 图快照 | `R003-G0007` |
| 文献来源 | `L001` |
| 计算运行 | `R003P01/E001` |

配对跨轮续做时，标识保留原始轮次前缀。
代理会话标识仅作辅助引用。
代理会话标识不替代逻辑角色或配对标识。
引用历史证据时，使用固定记录的标识、版本和实际路径。
`CURRENT.yaml`、`HEAD.yaml` 和 `final/` 是可变入口。
仅凭这些入口不足以标识固定历史证据。

## 2. 开始或恢复轮次——controller

1. 阅读用户目标、限制、修改和中断说明。
2. 旧轮需要补记暂停或恢复时，使用第 9 节。
3. 存在 `CURRENT.yaml` 时，读取文件。
4. 按顺序阅读最近交接：`START_HERE.md`、`RESULT.yaml`、`PROBLEM.md`、`FRONTIER.md`。
5. 阅读当前任务所需的完整事实记录。
6. 按用户约定选择原轮或新轮。
7. 在控制文件中记录精确目标和采用的口径。
8. 保存完整初始事实快照，包含适用的继承事实。
9. 完整快照保存后，更新图入口。
10. 向 researcher 分配文献任务。

没有既有状态时，初始化项目记录。
初始图可以不含已接纳成果。
新对话不会自动产生新轮次预算。
例行开始或恢复时，禁止读取 `additional_papers/`。

各记录包含以下内容：

| 记录 | 必要信息 |
| --- | --- |
| `README.md` | 项目目标、规则位置、日期与路径约定、采用口径的位置。阅读顺序、补充论文规则、暂缓功能。禁止另建进展台账。 |
| `CURRENT.yaml` | `project_id`、`current_round`、`current_fact_head`、`latest_handoff`。路径目标可用前，禁止填写路径。 |
| `PROBLEM.md` | 原题、精确目标、标识与修订版本。对象、量词、范围、假设、结论、定义引用。附加请求、不确定内容、修改。 |
| `ROUND.yaml` | 轮次标识、创建时间、前轮、目标版本与路径。输入图标识与路径、预算、已开始工作的配对标识。采用的口径、用户指示引用。 |
| `ROUTES.md` | 路线标识、目的、核心方法、来源材料、已接纳输入。与其他路线的差异、证明缺口、配对分配、结果或停止原因。 |
| `CHECKPOINT.yaml` | 最近完整图、正式提交、已完成审核、待完成审核。已接纳但尚未登记的成果、未完成请求。草稿或代码路径、下一步动作。 |

预算字段使用 `max_pairs`、`max_formal_submissions_per_pair` 和 `started_pair_ids`。
在口径中记录累计结果、已同意的部分成果范围和项目内原创性。
在口径中记录跨轮配对计数和提交计数。
依据正式记录计算次数。
禁止维护第 2 套独立预算台账。

目标改变时，保存新的问题版本，例如 `PROBLEM_r02.md`。
将 `ROUND.yaml` 指向实际采用的版本。
禁止让 controller 证明目标版本之间的等价性。

## 3. 文献调查——researcher

1. 检索前人成果、限制、反例、更正和未解决方向。
2. 阅读来源正文和理解结果所需的上下文。
3. 在 `research_papers/SOURCES.yaml` 中记录来源元数据。
4. 提取完整定义、假设、量词、范围和结论。
5. 为每条事实记录精确来源位置和记号变换。
6. 通过 `LITERATURE` 接纳忠实提取的文献事实。
7. 在 `RESEARCH.md` 中记录研究边界、目标缺口、准入事实标识和检索限制。
8. 向 controller 发送完整准入记录和路线材料。

检索片段是线索，不足以支撑完整定理。
来源不足时，将条目保留为线索。
禁止将猜想或实验观察作为已证定理接纳。
对已证命题，记录证明位置或原文引用的证明来源。
仅定义本身无须证明位置。
来源检查不包含 researcher 重新证明结果。

来源记录包含标识、标题、作者、年份、链接或文献标识。
同时包含版本、获取时间和访问限制。
取得 PDF 或其他可访问正文时，记录实际位置。
为每个文献修订版本保留不同的来源记录。
后续轮次使用同一版本时，复用原来源标识和 PDF。
禁止创建占位 PDF。

记号变换必须保持数学含义不变。
保持量词顺序、参数范围、范数、拓扑、正则性、一致性和常数依赖不变。
变换需要推导时，提交原事实，并请求配对任务。

文献结果直接解决目标时，提供明确的目标对应记录。
controller 可以据此报告结果，无须证明配对。
新证明或更强结果的附加请求仍是独立任务。
检索未命中的报告仅适用于实际检索范围。
禁止依据检索未命中主张世界范围的原创性。

用户指定补充论文时，仅读取 `additional_papers/` 中请求范围内的材料。
在 `RESEARCH.md` 和 `SOURCES.yaml` 中记录实际使用。
保留用户原路径和文件名。
论文可以留在原路径。
后续使用已接纳事实无须重新扫描目录。

## 4. 分配不同路线——controller

1. 按主要构造、归约和证明方法对比候选路线。
2. 移除尚未开始的重复计划。
3. 在剩余轮次名额内选择任务。
4. 为每个将开始工作的配对创建 `TASK.md`。
5. 向 worker 提供任务和允许的事实版本。
6. 为 worker 绑定单独的 verifier。
7. 配对开始证明或审核时，登记到 `started_pair_ids`。

引用相同背景定理不表示路线相同。
将拟议桥梁和预期引理保留为待证目标。
活动路线改换核心方法时，将新工作计为新配对。
同一方法内的修补保留在既有配对中。

`TASK.md` 包含配对标识、路线标识、创建轮次和固定角色标识。
同时包含目标、范围和提交上限。
包含初始图版本、输入事实、核心方法、路线差异和证明缺口。
包含预期产物、约束和停止条件。
保留任务实质变更记录。
禁止将其他配对的未准入证明作为输入分发。

## 5. 正式提交与审核——worker 和 verifier

### worker 流程

1. 阅读自己的 `TASK.md`、允许的事实和配对的前次审核。
2. 在已记录假设下推进指定路线。
3. 将有用草稿和具体失败步骤保存到自己的 `drafts/`。
4. 通过 controller 向 researcher 请求缺失的外部事实。
5. 必须改变核心方法时，向 controller 报告拟议修改。
6. 在剩余预算内准备下一次正式提交。
7. 在 `submissions/vNN/` 中固定提交内容。
8. 向固定 verifier 发送精确版本。

首次提交使用 `v01`，返工使用 `v02` 至 `v04`。
证明正文写入 `SUBMISSION.md` 或明确指定的 `proof.tex`。
每次正式提交仅保留 1 份权威证明正文。

记录正式送审时间、配对、worker、版本、目标版本和编号命题。
包含完整陈述、假设、事实版本、完整论证、计算、修改和未完成内容。
返工时，记录对每项审核缺陷的回应及修改影响。
审核期间，禁止修改已固定的提交。

### verifier 流程

1. 阅读固定 worker 的固定提交及精确依赖。
2. 对照目标和全部假设检查命题。
3. 检查事实可用性、版本和适用性。
4. 检查必要推导中的缺口和循环支持。
5. 检查量词、常数依赖、一致性和适用的边界情形。
6. 论证使用计算时，检查计算覆盖性和精确性。
7. 审核反例时，检查原假设和原结论失效。
8. 为精确提交版本编写 `reviews/vNN/REVIEW.md`。

审核记录包含 verifier、配对、提交版本、路径、范围、判决和原因。
审核判决使用 `ACCEPT`、`REWORK` 或 `INCOMPLETE`。
这些值是审核判决，不是轮次状态。
列出精确接纳命题、依赖、目标覆盖范围和未通过步骤。
同时列出位置、原因和剩余义务。

独立局部成果仅在依据完整且范围明确时准入。
整稿返工不取消局部准入。

为审核执行必要重算或诊断性反例搜索。
禁止暗中补全 worker 的证明。
审核后续提交时，复用未修改且不受影响部分的既有检查。
针对当前版本给出判决。

达到 4 次正式提交后，停止追加提交，除非用户明确增加预算。
保留已接纳局部成果和剩余义务。
已完成审核需要更正时，保留原报告。新增明确更正。

## 6. 发布已接纳事实——controller

1. 检查 researcher 或 verifier 准入判决的身份和精确范围。
2. 仅将已接纳内容复制到下一份完整图快照。
3. 记录适用的更正、支持变更和受影响依赖。
4. 使用新图标识保存快照。
5. 将 `fact_graph/HEAD.yaml` 指向完整快照。
6. 将 `CURRENT.yaml` 指向当前图入口。
7. 记录事件。
8. 更新检查点。

每份快照包含图标识和完整累计事实记录。
每条事实记录包含：

- 稳定标识、修订版本、对象类型。
- 完整陈述、量词、条件、参数范围、定义、记号、作用域。
- 直接依赖的标识和修订版本。
- 来源类型：`LITERATURE` 或 `DERIVED`。
- 精确来源，或提交中的命题及审核位置。
- 责任 researcher 或固定 verifier。
- 当前可用性、限制原因、更正或替代关系。
- 同一命题存在多个已接纳依据时，各项支持的独立记录。

`HEAD.yaml` 包含 `graph_id` 和 `snapshot_path`。
准入或修改已接纳陈述、支持、可用性后，发布新图快照。
修改草稿或拒绝未准入命题，无须产生新快照。
可以将一组准入记录合并发布。
保持旧快照原内容不变。
新事实版本不会自动使旧版本失效，也不会自动使旧证明适用于新陈述。

在 `audit/EVENTS.jsonl` 中记录重要事件。
事件包含标识、时间、责任角色、动作、对象标识、证据路径和必要说明。
事件引用原审核，不另复制第 2 份判决。
正式送审、完成审核、发布图或计划中断后，更新检查点。
无须保存每次编辑、工具日志或对话步骤。

## 7. 计算、论文与未解决事项

计算作为证据时，将固定代码、输入和输出保存在 `code/PAIR_ID/runs/RUN_ID/`。
在 `RUN.yaml` 中记录运行、配对、正式提交、目的和命令。
同时记录环境、依赖版本、输入方法、输出路径和限制。
使用随机性时，记录随机种子。
区分探索观察和证明主张。

worker 提供穷举、精确运算或严格数值界的数学论证。
verifier 审核这项论证。

需要交付论文时，使用 `src/main.tex`、`references.bib` 和 `CLAIMS.yaml`。
在 `CLAIMS.yaml` 中对应论文标签、精确事实版本和证明位置。
明确标记未解决主张。
controller 可以整理既有文本和编译论文。
将新的数学衔接交给配对。

发布 PDF 时，保存 `out/paper.pdf` 和 `BUILD.yaml`。
记录编译时间、固定源码位置、图版本、命令和必要工具。
为不同发布版本保留独立来源记录。

在 `FRONTIER.md` 中为事项分配稳定标识。
在 `RESULT.yaml` 中引用事项。

| 事项类型 | 必要记录和动作 |
| --- | --- |
| `MISSING_SPECIFICATION` | 缺失的目标信息、影响、已检索来源。researcher 无法补齐的原因、受影响任务、需要用户提供的信息。 |
| `LITERATURE_CONFLICT` | 精确冲突命题与来源位置、假设、量词、记号、版本。受影响依赖、已完成检查、未解决疑问。 |

定义或版本可能不同时，要求 researcher 检查来源语境和更正。
已接纳来源在相同条件下冲突时，停止使用争议支持和受影响依赖。
保持未受影响事实可用。
需要新数学判断时，在预算内分配配对。
已接纳文献反例直接证伪目标时，记录 `DISPROVED`，不再保留为未解决冲突。

## 8. 结束轮次——controller

目标解决、任务完成、预算耗尽或达到约定边界时，结束轮次。
原题说明缺失或文献冲突也可以结束受影响工作，并保留明确说明。
未发生中断的收尾仅使用必要名额和实际产物。
论文或 PDF 可交付可不交付。

1. 记录实际结束原因。
2. 汇总正式结果和未完成任务。
3. 登记尚未入图的已接纳事实。
4. 保存完整图快照。
5. 更新图入口。
6. 准备下表中的 5 个交接文件。
7. 对照来源记录检查目标版本、事实版本、判决、次数和证据路径。
8. 交接文件齐备后，在 `final/RESULT.yaml` 发布实际结束声明。
9. 在 `CURRENT.yaml` 中更新最近交接位置。
10. 连同来源记录保存实际论文和计算产物。
11. 清理前，将必要证据从 `temp/` 移到稳定位置。
12. 仅删除可以安全删除的临时材料。

| 交接文件 | 内容 |
| --- | --- |
| `START_HERE.md` | 目标、与 `RESULT.yaml` 一致的精确结果、关键事实、本轮变化。路线结果、限制、下一步动作、阅读路径。 |
| `RESULT.yaml` | 实际结束声明、结果依据、范围、剩余义务、事项、交接完整性。 |
| `PROBLEM.md` | 实际采用的目标版本副本，包含标识、修订版本和源路径。 |
| `FACTS.json` | 完整源快照的原样副本，包含图标识和事实可用性。 |
| `FRONTIER.md` | 未完成证明义务、路线位置、已接纳局部成果与条件。失败步骤、来源请求、事项、精确续接路径、剩余提交预算。 |

信息已知时，在 `RESULT.yaml` 中使用对应字段：

- `record_type: ROUND_END`、`round_id`、目标标识与修订版本、`recorded_at`。
- `result_status`、`result_scope`、`basis_fact_ids`、证据位置。
- `new_results_this_round`、`scope_note`、`remaining_obligations`。
- `source_graph_id`、`issues`、`handoff_complete`、`missing_files`。
- 第 9 节中适用的暂停和恢复字段。

以明确文献对应或 verifier 判决作为结果依据。
变化摘要放在 `START_HERE.md`，证据路径保留在既有记录中。
无须另建变化文件或自动索引文件。
交接必须说明轮次，无须读取全部对话历史。
详细检查来源时，可以引用 `final/` 之外的证据。
后续引用历史事实前，通过 `CURRENT.yaml` 检查当前可用性。

保留失败证明、退回提交、审核、快照和恢复所需草稿。
禁止将用户论文作为临时材料删除。
没有用户指示或既有约定时，禁止开始新轮次。

## 9. 暂停与恢复——controller

### 立即停止

1. 用户要求立即停止时，停止新研究工作。
2. 向活动子代理发送停止请求。
3. 在 `final/RESULT.yaml` 中保存可取得的最小暂停信息。

记录轮次、`run_status: PAUSE`、触发依据、实际记录时间和交接完整性。
包含已知结果、依据、最近可靠图、待完成工作和精确版本。
同时包含已用提交次数、缺失文件和下一步动作。
值未知时，省略对应字段。记录缺失信息。
禁止等待未完成工作或完整的 5 文件交接。

### 补记此前暂停

这 2 项依据互相独立。

| 依据 | 流程 |
| --- | --- |

### 续做

1. 定位最近完整且可识别的目标和图版本。
2. 从正式记录恢复文献准入和已完成审核判决。
3. 定位未完成配对、精确提交、审核进度和提交历史。
4. 区分已接纳事实、待审草稿和不完整文件。
5. 补登仅缺机械入图的已接纳成果。
6. 按用户约定记录所选续做轮次。
7. 研究继续前，保存恢复依据。

继续原轮时，保留全部已用配对名额和提交次数。
进入新轮时，每个实际继续证明或审核的配对计入本轮。
保留原配对身份、固定角色和累计提交次数。
在新配对目录中创建 `CONTINUE.yaml`，不再建立第 2 份独立原始任务。

同时引用最近完成的审核和全部正式提交。
记录当前图、输入变更、续做范围和计数口径。
旧证据保留在旧轮。
新轮仅保存新工作。
