# 数学研究流程

## 1. 入口与项目布局

执行本流程前，读取适用于该项目的指令。
用户要求研究、继续研究或整合论文时，使用本流程。
不要仅因用户编辑这些规则而开始研究。
项目规则规定角色、准入、预算和数学结果含义。

论文整合及其原创性核查采用第 10、11 节。
第 9 节仅用于中断的研究轮次。
读取分配角色对应的章节和必要任务记录。

所有持久路径均以项目根目录为基准。
使用用户时区。
项目默认时区为 `Asia/Shanghai`。
轮次在项目内连续编号。
不同日期继续同一工作时，保留轮次目录中的创建日期。

文件树表示允许的位置。只在必要的研究阶段创建文件。
`R003`、`R003P01`、`L001` 和日期均为示例。

保留 8 类轮次目录功能和共享项目事实图。
空目录可选。
禁止创建空证明、空审核、空 PDF 或未来提交版本。

采用以下稳定标识形式：

| 对象 | 示例 |
| --- | --- |
| 目标与修订 | `T001@r1` |
| 逻辑配对 | `R003P01` |
| 路线 | `ROUTE00301` |
| 正式提交 | `R003P01/v02` |
| 事实与修订 | `F0042@r1` |
| 支持与修订 | `S0017@r1` |
| 项目事实图 | `G0008` |
| 论文任务与配对 | `PAPER001`、`PAPER001P01` |
| 文献来源 | `L001` |
| 计算运行 | `R003P01/E001` |

每对属于一个研究轮次或一个论文任务。
新轮次和新论文任务使用新配对标识。
同轮恢复时保留配对标识。
继承事实保留原标识、修订和来源引用。

agent 会话标识仅作为附加引用。
不能用它替代逻辑角色或配对标识。
历史证据引用固定记录及其标识、版本和真实路径。
`CURRENT.yaml`、`HEAD.yaml` 和 `final/` 是可变入口。
仅凭这些入口不足以标识固定历史证据。

## 2. 开始新轮——controller

新轮仅接收用户要求、`CURRENT.yaml`、当前事实图和最新 `final/` 总结。
禁止为了开始新轮读取旧配对目录、提交、审核、草稿或检查点。
补记此前暂停或续做中断轮次时，使用第 9 节。
仅有暂停记录不表示需要恢复执行。
新轮设置前，完成第 9 节要求的必要确认。

1. 读取用户目标、限制、变化和中断报告。
2. `CURRENT.yaml` 存在时，读取该文件。
3. 按顺序读取最新交接：`START_HERE.md`、`RESULT.yaml`、`PROBLEM.md`、`FRONTIER.md`。
4. 读取当前任务所需的完整事实记录。
5. 符合恢复条件时，改用第 9 节。
6. 在控制文件记录新轮、精确目标、策略和新预算。
7. 设置 `started_pair_ids` 为 `[]`。
8. 记录固定已发布输入图版本。禁止每轮复制快照。
9. 事实图不存在时，按第 6 节发布初始项目图。
10. 向 researcher 分配文献任务。

没有旧状态时，初始化项目记录。
初始图可以不含已接纳成果。
通过根目录 `fact_graph/HEAD.yaml` 读取当前事实。
禁止用旧交接中的图覆盖较新的当前图。
新对话不自动创建新轮预算。
例行启动或恢复时，禁止读取 `additional_papers/`。

为本轮创建新配对标识、角色分配和 `TASK.md`。
每对正式提交从 `v01` 开始。
禁止将旧配对、待审核事项或已用提交次数转入新轮。

记录内容如下：

| 记录 | 必需信息 |
| --- | --- |
| `README.md` | 项目目的、规则位置、日期和路径约定、采用策略的位置、读取顺序、补充论文规则、延期功能。不另建进度台账。 |
| `CURRENT.yaml` | `project_id`、`current_round`、`current_fact_head`、`latest_handoff`。`current_fact_head` 指向根目录 `fact_graph/HEAD.yaml`。目标存在后才填写路径。 |
| `PROBLEM.md` | 原问题、精确目标、标识和修订。对象、量词、范围、假设、结论、定义引用、额外要求、不确定项和变化。 |
| `ROUND.yaml` | 轮次标识、创建时间、上一轮、目标修订和路径。固定输入和输出图、预算、已启动配对、策略和用户指令引用。 |
| `ROUTES.md` | 路线标识、目的、核心方法、来源、已接纳输入、区别特征、证明缺口、配对分配、结果和停止原因。 |
| `CHECKPOINT.yaml` | 最近完整图、提交、已完成审核、待审核事项、待写入准入。未结请求、草稿或代码路径、下一步。 |

预算字段使用 `max_pairs`、`max_formal_submissions_per_pair` 和 `started_pair_ids`。
在策略中记录累计结果、已同意的部分成果范围和项目级新颖性。
每轮分别计算配对和提交次数。同轮跨暂停和会话保留已用次数。
根据当前轮次的正式记录计算次数。
不维护独立的第二套预算台账。

目标变化时，保存新问题版本，例如 `PROBLEM_r02.md`。
`ROUND.yaml` 指向正在使用的版本。
禁止要求 controller 证明目标版本之间的等价性。

## 3. 文献研究——researcher

1. 检索前人成果、限制、反例、勘误和开放方向。
2. 读取来源正文及理解结果所需的上下文。
3. 在 `research_papers/SOURCES.yaml` 记录来源元数据。
4. 提取完整定义、假设、量词、范围和结论。
5. 记录每项事实的精确来源位置和记号变化。
6. 通过 `LITERATURE` 接纳忠实文献事实。
7. 在 `RESEARCH.md` 记录边界、目标缺口、准入事实标识和检索限制。
8. 向 controller 提交完整准入记录和路线材料。

检索摘要只作为线索，不足以支持完整定理。
来源不足时，保留为线索。
禁止将猜想或实验观察接纳为已证定理。
已证命题须记录证明位置，或原文引用的证明来源。
仅定义本身无须证明位置。
这一来源检查不要求 researcher 重做证明。

每条来源记录包含标识、标题、作者、年份、链接或文档标识、版本、检索时间和访问限制。
可用时，填写真实 PDF 路径或其他原文位置。
每次来源修订分别记录。
后续轮次使用相同来源版本时，沿用相同来源标识和 PDF。
禁止创建占位 PDF。

记号变化须保持数学含义不变。
保留量词顺序、参数范围、范数、拓扑、正则性、一致性和常数依赖。
变换需要推导时，提交原始事实并请求配对任务。

文献结果直接解决目标时，提供明确的目标对应记录。
controller 可以据此报告结果，无须证明配对。
新证明或更强结果的额外要求仍是独立任务。
检索未成功时，只报告实际检索范围。
禁止仅凭检索未命中声称全局原创。
论文原创性主张采用第 11 节的完整核查。

用户指定补充论文时，只读取 `additional_papers/` 中的指定材料。
在 `RESEARCH.md` 和 `SOURCES.yaml` 记录实际使用。
保留用户原始路径和文件名。
论文可以留在原路径。
后续使用已接纳事实，无须重新扫描目录。

## 4. 分配不同路线——controller

本路线流程适用于研究轮次。论文工作采用第 10 节的范围和上限。

1. 按主要构造、归约和证明方法比较候选路线。
2. 重复方案开始工作前，移除重复方案。
3. 在未用轮次名额内选择任务。
4. 为即将启动的配对创建 `TASK.md`。
5. 向 worker 提供任务和允许的事实版本。
6. 为该 worker 绑定独立 verifier。
7. 证明或审核开始时，将配对记入 `started_pair_ids`。

共享背景定理不代表路线相同。
拟议衔接和预期引理保持为未证目标。
活动路线改用不同核心方法时，新工作计为新配对。
同一方法的返工保留在原配对。

`TASK.md` 记录配对、所属轮次或论文任务、固定角色、目标、范围和提交上限。
填写输入图、允许的事实、预期输出、约束和停止条件。
研究路线另写路线标识、核心方法、区别特征和证明缺口。
盘点、原创性、主稿和表述工作无须虚构证明路线。
记录任务的实质变化。
禁止分发另一配对的未接纳证明作为输入。

## 5. 提交与审核——worker 和 verifier

### worker 流程

1. 读取 `TASK.md`、允许的事实和本对此前审核。
2. 在记录的范围和假设内完成路线或论文工作。
3. 将有用草稿和具体失败步骤存入本对 `drafts/`。
4. 通过 controller 向 researcher 请求缺失外部事实。
5. 研究路线须改变核心方法时，向 controller 报告。
6. 在剩余预算内准备下一次正式提交。
7. 在 `submissions/vNN/` 中固定提交内容。
8. 向固定 verifier 发送精确版本。

首次提交使用 `v01`。每次正式返工递增版本，并遵守任务实际限额。
证明写入 `SUBMISSION.md` 或明确指定的 `proof.tex`。
每次提交只保留一份正式证明正文。
非证明工作提交分配的报告。
按第 12 节提供独立 `PROOF_IDEA.md`，绑定同一提交版本。

记录正式送审时间、配对、worker、版本、目标修订和编号命题。
包含完整陈述、假设、事实版本、完整论证、计算、变化和未完成工作。
使用特定证明或方法时，注明精确支持版本或固定证明提交。
返工时，记录对每项审核缺陷的回应及修改影响。
审核期间禁止编辑固定提交。

### verifier 流程

仅审核固定 worker 的提交。论文报告按分配范围核查报告和证据。

1. 读取固定 worker 的提交及精确依赖。
2. 对照目标和全部假设检查命题。
3. 检查事实可用性、版本和适用性。
4. 检查每项必要推导的缺口和循环支持。
5. 检查量词、常数依赖、一致性和适用边界情形。
6. 论证使用计算时，检查覆盖范围和精度。
7. 对反例检查原假设及原结论失效。
8. 按第 12 节核查 `PROOF_IDEA.md`。
9. 为精确提交版本编写 `reviews/vNN/REVIEW.md`。

审核记录 verifier、配对、提交版本、路径、范围、判决和理由。
判决采用 `ACCEPT`、`REWORK` 或 `INCOMPLETE`。
这些是审核判决，不是数学结果或论文完成状态。
列明精确准入命题、依赖、目标覆盖、拒绝步骤、位置、理由和剩余义务。

依据完整且范围明确时，接纳独立局部成果。
整份证明需要返工，不撤销该局部准入。
单独记录数学准入、证明思路核查和必要论文检查。
说明或原创性核查未完成，不撤销明确的数学准入。
必要检查未完成时，相应交付仍未完成。

审核可以使用必要的重算或诊断性反例。
禁止静默补齐 worker 的证明。
后续提交复用未改变且未受影响部分的检查。
对当前版本给出判决。

适用上限前，先完成最后一次允许提交的审核。
达到上限后停止新提交。研究配对采用轮次策略，论文配对采用第 10 节。
保留已接纳局部成果和剩余义务。
修正已完成审核时，保留旧报告并新增明确修正。

### 正式提交计数

轮次和论文任务采用相同计数规则，以及各自的上限。
固定版本送达固定 verifier 并请求正式判决时，计为 1 次。
送达时计数，不以接纳为条件。根据正式记录分别计算每对次数。
一次送审可以包含多个命题和缺陷，不按条目计次。

草稿交流、来源检索、语言修改、排版和编译本身不增加次数。
请求正式判决的报告计次。
已提交内容有任何修改时，下次正式判决请求须使用新版本并计次。
这包括论证、引用、说明、语言和排版。
继续审核同一版本或编译未变的固定源码，不增加次数。

此前所有提交和审核保持不变。
禁止通过改名、新会话或替代 agent 重置次数。

在一份审核中列明当前版本发现的缺陷。
复用未改变且未受影响材料的检查。
接纳后无必要修改时，停止提交。禁止无目的地使用预算。

## 6. 发布与读取项目事实图——controller

仅 controller 发布共享项目事实图。
研究轮次和论文任务共用根目录的 `fact_graph/`。
图标识在项目内唯一，不采用按轮次划分的图编号。
区分提交、事实、支持和图版本。

| 记录 | 必需内容 |
| --- | --- |
| `HEAD.yaml` | 当前 `graph_id`，以及指向图清单的 `graph_path`。 |
| `facts/F0042/r1.json` | 稳定标识、修订版本、逻辑类型和完整陈述。定义、量词、假设、记号、参数范围和适用范围。 |
| `supports/S0017/r1.json` | 标识、修订版本、精确目标事实、准入渠道和判决。精确依赖、证据路径、负责角色和来源任务。 |
| `graphs/G0008.json` | 图标识、发布时间、前一图和发布原因。完整累计事实与支持引用、可用状态和原因。 |
| `index.jsonl` | 每行一条检索记录。源图、事实标识和修订、名称、主题、关键条件、可用状态和路径。 |

定义和依赖引用使用精确版本，例如 `F0042@r1`。
每份支持具有独立依赖，不能把替代支持混为共同前提。
原始证据保留在来源任务中。引用固定来源或提交与审核版本。
可变草稿或最新稿件不能作为固定证据。

普通定理使用注明事实版本。
使用或主张特定证明、构造或方法时，还须注明支持或固定证明版本。

已有事实的新证明需要通过 `DERIVED` 接纳新的支持。
该事实的其他有效支持不能确立这份证明。

一份支持失效时，保留精确陈述的其他已接纳且适用的支持。
停止受影响支持及缺少有效适用支持的依赖成果。
将新数学判断交给 researcher 或固定配对。controller 不能代为判定。
循环依赖不能确立证明。联合归纳需要已准入的完整论证。

1. 核对准入判决的身份和精确范围。
2. 保存新的事实和支持版本。
3. 保存新图清单、可用状态及原因。
4. 核对全部引用和精确版本对应关系。
5. 所需记录齐全后，更新 `HEAD.yaml`。
6. 重新生成该图的检索索引。
7. 在来源任务中记录发布事件。
8. 属于研究轮次时，更新检查点。

`CURRENT.yaml.current_fact_head` 指向根目录 `HEAD.yaml`。
禁止在 `CURRENT.yaml` 保存第二份当前图标识。
`ROUND.yaml` 和 `PAPER.md` 引用固定输入和输出图版本。
首个图须先保存记录和清单，再设置入口。
中断记录引用最近完整发布的图。

已发布事实、支持和图清单文件保持不变。
陈述、假设或定义变化时，创建事实修订。
独立证明新增支持，无须修改事实陈述。
证明证据或依赖变化时，创建支持修订。

可用状态变化或撤回时，创建图清单并记录原因。
新事实修订的支持必须以该修订为目标。
适用性判决可以引用旧固定证明，无须复制正文。
禁止自动转移证明或替换依赖。

图清单可以包含同一事实的多个修订。
包含全部精确依赖记录及状态。
保留撤回或无效记录的标识、状态和原因。

完整清单及引用记录构成完整图，无须重复复制数学正文。
历史复现使用该图中的状态。
新使用历史事实时，还须检查当前可用性。
草稿编辑和候选命题被拒绝，无须发布新图。
可以一起发布多份准入记录。

### 按需读取

索引用于发现记录，不作为数学证据。
索引缺失或过期时，重新生成索引，或直接读取固定清单。
查询可以筛选标识、主题、可用状态、来源任务或图版本。
每次查询固定一个图版本。返回精确的依赖、反向依赖和历史引用。

1. 检索目录中的候选事实。
2. 读取选中事实的完整陈述和准入依据。
3. 读取必要依赖、支持和来源证据。

保留量词顺序、参数范围、常数依赖、正则性、拓扑和一致性条件。
区分存在性、唯一性、必要性和充分性。

语言修改影响数学内容时，重新审核受影响的陈述和论证。
纯语言或排版修改，不要求重复检查未受影响的证明。
内容修改后的正式交付仍遵守提交计数规则。

## 11. 论文整合中的原创性核查

核查所声明的贡献，不追溯每个标准证明步骤的全部历史。
区分正确性、原创性和重要性。
在本项目中独立推导，不代表具有全局原创性。
主要结果、改进和新方法须完成全面核查。
对声称具有独立价值的新引理或例子，采用针对性核查。

标准工具须检查归属和适用条件。
“首次”“最早”或“唯一已知方法”等声明须另查优先权。
数学上的唯一性按普通证明和准入处理，不以文献优先权核查替代。

主要贡献的检索须覆盖以下来源类型：

- 数学索引，例如 zbMATH Open 或可访问的 MathSciNet。
- 预印本及更新，例如 arXiv、作者主页、修订和勘误。
- 定向网页检索及直接相关的引文路径，包括书籍和讲义。

检索替代术语、等价陈述、可覆盖该结果的更一般结论和已有证明方法。
兼顾早期与近期工作。只追查可能改变贡献判断的线索。
引文追查必须有停止条件。

不要求使用每个平台。访问失败时使用其他来源，并记录限制的影响。
关键来源无法查阅时，仅将受影响的原创性声明保留为待定。

阅读关键原始来源，对照精确陈述和证明位置。
检索摘要和文本相似性检查不能替代数学比较。

反对意见须指出来源、可能的等价或推导，或具体且影响判断的检索缺口。
尚无完整重合证明时，具体线索也足以触发针对性核查。
确认重合须提供精确来源位置和数学覆盖证据。

原创性 worker 提供所需的新论证，由其固定 verifier 审核。
verifier 可以提出线索，但不能自行接纳自己未经审核的推导。
可独立使用的新等价结果或归约仍须通过 `DERIVED`。原创性不是第三种准入渠道。

蕴含关系 `A ⇒ B` 确立数学联系，不代表不存在任何贡献。
检查新论证、方法或联系增加了什么。
简单改名或常规代入，通常只形成重述或推论。
已知结论使用不同证明时，检查所声明的证明或方法贡献。
检查假设、范围、界和结论的实际变化。
未能证明重合，本身不能证明原创性。

对每项贡献完成以下检查：

1. 写明精确声明和拟主张的原创性类型。
2. 覆盖适用来源类型和主要陈述变体。
3. 阅读并比较可能覆盖该结果的关键来源。
4. 解决具体重合疑点，记录判断依据。

解决疑点也可以是确认重合并调整贡献声明。
先做初步检索，再针对具体缺口补查。
检查完成且没有新线索后，停止一般性检索。
时间、检索次数和预算耗尽，均不能替代检查完成条件。

| 发现 | 处理 |
| --- | --- |
| 前人成果覆盖该结果 | 引用该成果，修改贡献声明。 |
| 检查已完成，未发现覆盖，具体疑点已解决 | 允许对已核查的贡献作正常原创性声明。 |
| 仍有影响判断的疑点 | 写明缺少的证据。该原创性声明保持待定，不称为已确认的新工作。 |

仅凭检索未命中，不能确立原创性。
完成检查后，抽象的未知文献可能性不能阻止判断或导致无止境检索。
不要求证明任何现有理论都无法推出该结果。
可以在已接纳范围内，将核查过的贡献称为新定理、新证明或新方法。
不要求每项贡献都加“仅在本项目中新”或“据我们所知”。
具体优先权声明需要限定时，再加限定。

记录贡献和证明版本、检索日期、范围、查询词及来源位置。
同时记录比较、访问限制、疑点和判决。
这些记录保存在同一论文任务的配对提交和审核文件中。
`INVENTORY.md` 引用这些判决，不另建判决记录。

出现具体新来源或实质贡献变化时，仅重开受影响的检查。
纯语法和排版修改不重开原创性检查。
日后发现前人成果时，纠正归属，保留另有依据的新贡献。
原创性未决不撤销数学准入，但可能妨碍论文核心贡献的必需检查完成。

## 12. 面向人类读者的证明思路

每对研究或论文配对的每次正式提交，都须附带 `PROOF_IDEA.md`。
由 worker 撰写，固定 verifier 核查。
与所提交的论证或报告保存在同一 `submissions/vNN/` 目录。
文件与该版本一同固定。修改后再次请求判决，须新建版本并计数。

解释问题的哪些特征提示了所选方法。
通常写 1 至 3 段；必要时加入简单例子或特例。
说明具体线索、选路理由、要克服的障碍，以及最不直观的构造或变换。

区分直觉、类比和已证明步骤。

同时检查未解决缺口和来源证据。

必需的思路说明仍影响交付完成，并使用任务剩余提交额度。
额度耗尽时，保留已接纳结果，记录未完成说明，不自动增加提交。
