# 数学研究规则

版本：0.2.0。

## 1. 范围与术语

本规则适用于本项目的数学研究和论文整合。
本文件可以独立使用。配套研究技能提供可选的操作细节。
读取全部 10 节。提供的副本不完整时，工作前读取完整项目文件。
不要仅因用户编辑这些规则而开始研究。

| 术语 | 含义 |
| --- | --- |
| 目标 | 精确的数学问题及其版本。 |
| 路线 | 一种证明方法或反例方法。 |
| 配对 | 同一轮次或论文任务内，工作范围明确的一名固定 worker 与一名固定 verifier。 |
| 轮次 | 具有目标和配对上限的研究工作。 |
| 论文任务 | 将累计成果整合为论文的任务，独立于研究轮次。 |
| 准入 | 通过 `LITERATURE` 或 `DERIVED` 接纳。 |
| 事实 | 具有完整条件和逻辑类型的数学陈述。 |
| 支持 | 精确事实版本的一份来源或已接纳证明，具有独立的依赖关系。 |
| 图清单 | 某一图版本中的完整事实与支持引用，以及可用状态。 |
| 提交 | 送交正式审核的固定工作版本。 |
| 交接 | 记录结果及后续工作依据的材料。 |

## 2. 角色

使用 Codex subagent 承担 researcher、worker 和 verifier 职责。
向每个 subagent 提供角色、允许的输入、任务和输出路径。
并行容量不足时，按顺序执行任务。
必要角色无法运行时，报告限制。禁止将证明或审核职责转交 controller。
角色指令不构成沙箱隔离。

| 角色 | 职责与限制 |
| --- | --- |
| controller | 读取来源、规划路线、安排配对、管理预算和记录、发布准入成果、编译论文。禁止证明、修补或判定数学内容。 |
| researcher | 检索并忠实提取具有完整条件和精确来源的文献事实。禁止将新推导记作文献摘录。 |
| worker | 完成分配的路线或论文工作，提交论证或报告，修复缺陷。禁止自行批准工作。 |
| verifier | 仅审核固定 worker 的提交。接纳明确成果或要求返工。禁止静默补齐证明。 |

返工期间保持配对身份和固定角色。
禁止为了取得不同判决而更换 verifier。
任务仍在执行时，替代 agent 可以沿用同一历史和预算继续原角色。
这种替换不允许恢复已经中断的论文任务。
将审核中产生的新推导交回 worker，要求正式提交。

## 3. 数学边界

在目标记录中保留原问题、定义、量词、范围、假设和结论。
将新证明或更强结果的要求与目标的数学状态分开记录。
目标变更时，保留旧版本和原因。
单独记录受限或较弱的命题，不能用它们替代原目标。
将必要的等价性证明交给配对。

仅采用以下准入渠道：

- `LITERATURE`：researcher 接纳具有完整条件和精确来源位置的忠实摘录。
- `DERIVED`：固定 verifier 从其 worker 的固定提交中接纳明确命题。

无须为每项文献结果安排新证明或第二名 verifier。
区分定义、局部假设、已接纳定理、猜想和观察。
存在性、唯一性和等价性主张需要证据，包括附在定义中的主张。

引用既有结果时，使用事实图中允许且可用的事实。
记录基本逻辑和项目约定，无须为每步算术建立事实节点。
向 researcher 请求缺失的外部事实。
模型记忆、路线建议和未接纳草稿不能作为既有前提。
证明内部可以包含完整的局部推导。其他任务引用为既有事实前，须先准入。

跨配对共享已接纳事实、来源请求、候选陈述、方法概述和行政进度。
未接纳证明全文限于本配对和 controller 的行政管理范围。
其他配对可以接收候选命题作为待证目标，不能作为已接纳前提。

在预算内将新的数学衔接交给配对。
原配对可以在原工作范围和剩余预算内完成衔接。
研究路线改用不同核心方法时，须建立新配对。
论文结构或语言修改继续使用原论文工作范围和预算。
总结不能替代证明。使用 `L ⇒ T` 确立 `T` 前，先提供 `L` 的已接纳支持。

在提交中记录精确的事实依赖版本。
使用特定证明、构造或方法时，还须注明支持版本或固定证明提交。
已有事实的新证明需要新的 `DERIVED` 支持，其他支持不能确立该证明。
不能仅因历史图包含某个前提，就使用已知无效或有争议的前提。
循环依赖不能确立证明。联合归纳需要已接纳的完整论证。

证明有缺陷不表示命题为假。
停止使用受影响的支持，以及缺少有效适用支持的依赖成果。
保留精确命题的其他已接纳且适用的支持。
将新的数学判断交给 researcher 或固定配对，记录变化和原因。
计算需要 worker 论证覆盖范围、精度和充分性，再由 verifier 审核。
代码运行成功或 PDF 编译成功不构成数学审核。

## 4. 预算、判决与结果

### 研究预算

用户未指定不同数值或结果规则时，采用以下默认值。
在 `ROUND.yaml` 中记录采用的规则，并落实用户的明确修改。

| 项目 | 默认值 |
| --- | --- |
| 配对上限 | 每轮 4 对，也可选用 3 对。所有开始证明或审核工作的配对均计入。 |
| 提交上限 | 每对 4 次，包括首次提交和 3 次返工。 |
| 历史 | 同一轮次跨暂停和会话保留次数。新轮建立新配对并重新计数。 |
| 结果范围 | 精确目标的累计进展。单独列出本轮新增结果。 |
| 新成果 | 在本项目推导并准入的成果。全局原创性须另行核查。 |
| 部分成果 | 已准入的受限结果、实质引理、较弱结论、部分参数结果或严格归约。 |

探索、组合证明和独立引理任务占用配对名额。
同一配对的返工和恢复不增加名额。
文献工作、路线规划、事实读取和行政恢复不占名额。
完成或失败的配对不退还名额。配对上限不等于并发上限。
可以保留一个未用名额，供本轮后续工作使用。

研究配对超出上限或自动连续开展新轮前，取得用户明确同意。
新会话不重置预算。使用同轮预算前，先恢复未知的已用次数。

### 提交计数与审核

以下计数规则适用于研究轮次和论文任务，两类任务采用各自上限。
固定版本送达固定 verifier 并请求正式判决时，计为 1 次，不以接纳为条件。
根据正式记录计算每对次数，不维护独立的另一套计数。
一次提交可以包含多个命题或缺陷，不按条目分别计次。

草稿交流、检索、文本修改、排版和编译本身不计次。
请求正式判决的报告计为提交。
修改已提交内容后，下一次正式送审须使用新版本并计次。
这包括论证、引用、证明思路、语言和排版。
继续审核同一版本，或使用未变的固定源码编译，不重复计次。
禁止通过改名、新会话或替代 agent 重置次数。

完成最后一次允许提交的审核。
集中列出发现的缺陷，复用未改变且未受影响部分的检查结果。
审核判决使用 `ACCEPT`、`REWORK` 或 `INCOMPLETE`，不能作为数学结果状态。
对完整独立命题的明确准入，不因其他命题返工而撤销。

将数学准入与证明思路核查、原创性核查及交付完成分别记录。
说明或原创性核查失败，不撤销已准入数学成果或已确立的结果状态。
必要检查未完成时，相应交付仍未完成，修订使用剩余提交预算。
接纳后无必要修改时，停止提交，不能无目的地用满额度。

### 数学结果

| 结果 | 证据 |
| --- | --- |
| `PROVED` | 已准入证明或精确匹配的文献结果确立原目标。 |
| `DISPROVED` | 已准入反驳适用。反例满足假设并违反结论。 |
| `PARTIALLY_RESOLVED` | 原目标仍开放，已准入项目成果满足部分成果规则。 |
| `UNRESOLVED` | 原目标仍开放，没有满足该规则的已准入项目成果。 |

单独记录额外要求及其完成状态。
证明失败、预算耗尽和检索无结果，均不能确立证明或反驳。
未知不等于 `UNRESOLVED`。结果未知时省略 `result_status`，记录缺失证据。
明确列出新增假设。

将 `MISSING_SPECIFICATION` 和 `LITERATURE_CONFLICT` 记为事项，不能作为数学结果值。
证明缺口不等于缺失规格。
只停止受影响的工作。controller 不能编造目标或裁决数学冲突。

记录不一致的假设。
配对或正式提交预算耗尽不表示中断。
平台使用额度这类外部限制可能中断执行。研究中断遵循第 7 节。

## 5. 记录与项目事实图

仅 controller 更新共享控制文件并发布事实图。
忠实记录准入。固定提交、已完成审核和已发布记录保持不变。
区分提交、事实、支持和图版本。采用稳定标识和项目相对路径。
使用用户时区，默认 `Asia/Shanghai`。

连续编号 `rounds/yyyy_mm_dd_roundNNN/`，续做时保留创建日期。
按需创建记录，不创建空证明、空审核、空 PDF 或未来提交。

| 记录 | 必需内容 |
| --- | --- |
| `README.md` | 项目目的、规则和策略位置、路径和日期约定、读取顺序、补充论文规则、延期功能。不另建进度台账。 |
| `CURRENT.yaml` | `project_id`、`current_round`、`current_fact_head`、`latest_handoff`。目标存在后才填写路径。`current_fact_head` 指向根目录 `fact_graph/HEAD.yaml`。 |
| `PROBLEM.md` | 精确目标、标识、修订版本、来源、额外要求、不确定项和变化。旧版本分别保留。 |
| `ROUND.yaml` | 轮次、创建时间、上一轮、目标版本和路径。固定输入和输出图、用户要求、策略、预算和已启动配对。 |
| `ROUTES.md` | 路线标识、方法、差异、已准入输入、缺口、分配、结果和停止原因。 |
| `CHECKPOINT.yaml` | 最近完整图、提交、审核、待发布准入、未结请求、工作路径和下一步。内容以正式记录为准。 |

研究预算字段为 `max_pairs`、`max_formal_submissions_per_pair` 和 `started_pair_ids`。
每轮保留 `code/`、`audit/`、`src/`、`out/`、`research_papers/`、`pairs/`、`final/` 和 `temp/`。
共享的 `fact_graph/` 位于项目根目录。

| 记录 | 必需内容 |
| --- | --- |
| `code/PAIR_ID/runs/RUN_ID/` | 固定代码、输入、输出和 `RUN.yaml`。记录命令、环境、依赖、随机种子和限制。 |
| `audit/` | `EVENTS.jsonl` 记录时间、角色、动作、对象和证据。详细恢复记录和已替换交接遵循第 7 节。 |
| `research_papers/` | `RESEARCH.md` 记录发现、缺口、准入和检索限制。`SOURCES.yaml` 记录标识、作者、标题、年份、版本、链接、检索日期、访问限制和可用文件路径。可用 PDF 存入 `pdf/`。 |
| `pairs/PAIR_ID/` | `TASK.md`、`drafts/`、`submissions/vNN/SUBMISSION.md`、`submissions/vNN/PROOF_IDEA.md`、`reviews/vNN/REVIEW.md`。 |
| `src/`、`out/` | 源码、命题映射、可选 PDF 和构建记录，采用第 8 节的论文形式。 |

文献记录给出陈述和证明位置、引用的证明来源，以及记号变化。
读取原文上下文，摘要只作为线索。保持含义，将必要推导交给配对。

任务记录配对、所属轮次或论文任务、固定角色、目标和范围。
同时记录允许的事实、输出、约束和上限。
仅研究路线任务需要路线和核心方法字段。

提交记录 worker、配对、版本、送审时间、目标版本和命题。
同时记录条件、依赖、论证、计算、变化和未完成工作。
回应此前缺陷。审核记录 verifier、精确提交及路径、范围、判决和理由。
同时记录准入、依赖和剩余义务。
保留原判决和修正历史。

正式送审、审核完成、图发布或计划中断后，更新研究检查点。

使用精确的定义和依赖版本。分别记录替代支持的依赖。

证据保留在来源任务的固定路径，不能用可变草稿替代。
图清单包含全部依赖记录和状态、同一事实的多个修订，以及撤回记录和原因。
图清单及其引用记录共同构成完整事实图。

数学内容变化需要新增事实修订。独立证明需要新增支持。
证明证据或依赖变化需要新增支持修订。可用状态变化需要新图清单及原因。

禁止自动转移证明或替换旧依赖。
新事实修订的支持必须以该修订为目标。

5. 所需记录齐全后，更新 `HEAD.yaml`。
6. 重新生成索引。

历史复现使用历史状态，新使用还须确认当前可用性。

### 读取、迁移与导出

索引用于定位记录，不作为数学依据。
索引缺失或过期时，重新生成索引，或读取固定图清单。
每次查询固定一个图，按标识、主题、状态、来源任务或图版本检索。
依赖、反向依赖和历史查询返回精确版本。
先读取目录，再读取选中事实的正文和准入依据，再展开必要依赖和证据。
摘要不能替代数学条件。

普通研究读取必要记录。整合任务遍历范围内的全部目录并记录覆盖情况。
完成盘点后，选择详细证据。

每批记录范围、剩余记录和后续读取位置。截断结果或靠前命中不构成完整盘点。
脚本可以遍历引用而不返回全部正文。不要求特定查询工具或安装路径。

迁移时保留旧快照、交接、标识、版本、依赖、状态和来源。
先分离陈述、支持和状态，再比较事实。仅支持或状态变化不构成陈述冲突。
相同版本只存一份，并建立旧图到新清单的对应关系。禁止编造缺失数据。
切换入口前，解决影响历史解析的身份冲突，并检查当前完整性和历史复现。

独立数据包包含所选图清单、全部引用事实和支持、依赖，以及必要本地证据。
保留项目相对路径、外部来源版本和访问限制。仅有图引用不足以构成独立交接。

声明单图或完整历史范围。完整历史包含全部已发布清单和引用记录。
索引可选且可以重建。导出数据不作为另一套可修改的正式依据。

项目可以有空的 `additional_papers/`。保留已有用户文件。
禁止例行列目录、扫描、读取或监控。只读取用户指定材料，记录使用和准入。
清理时保留用户论文，以及必要的角色检查和数学计算代码。

## 6. 新轮与交接

新轮仅接收用户要求、`CURRENT.yaml`、当前事实图和最新 `final/` 总结。
禁止为了开始新轮扫描旧配对、提交、审核、草稿或检查点。
需要补记暂停确认时，执行第 7 节。仅有暂停记录不授权恢复执行。

1. 读取目标、限制和可用的 `CURRENT.yaml`。
2. 读取最新交接总结和必要的完整事实。
3. 符合同轮恢复条件时，改用第 7 节。
4. 记录新轮、目标、策略、预算和固定已发布输入图。
5. 分配文献研究并记录准入。
6. 在配对上限内选择不同路线。
7. 向固定配对分配任务和允许的事实。
8. 配对开始证明或审核时，记录该配对。
9. 在预算内提交固定工作版本。
10. 按精确范围和依赖发布准入事实。

设置 `started_pair_ids` 为 `[]`，创建新配对和 `TASK.md`，提交从 `v01` 开始。
不继承旧配对任务、待审核事项或已用次数。

继承事实保留原标识、修订和来源。
使用根目录 `HEAD.yaml`。旧交接不能覆盖论文整合产生的较新图。
记录输入图，不复制初始快照。首个图按第 5 节初始化。

文献直接解决目标时，记录精确对应关系，该结果无须另建证明配对。
单独记录额外要求。

目标解决、工作完成、研究预算耗尽或到达约定边界时，结束本轮。
缺失规格或冲突导致受影响工作结束时，解释原因。
正常结束时，在 `final/` 发布以下 5 个文件：

| 文件 | 内容 |

## 9. 论文整合中的原创性

核查所主张的贡献，不调查每个标准步骤的完整历史。

主结果、改进和方法采用完整核查。具有独立价值的新引理或例子采用定向核查。

标准工具检查归属和适用条件。
“首次”“最早”“唯一已知方法”这类文献表述需要优先权核查。
数学唯一性采用普通证明和准入规则。

覆盖数学索引、预印本和更新、定向网络和引用检索，包括专著与讲义。
例如 zbMATH Open、可访问的 MathSciNet、arXiv、作者主页、修订和勘误。
检索早期及新近工作中的替代术语、等价陈述、更一般的覆盖结果和已有方法。
只追踪可能改变判断的线索，禁止无限递归引用检索。

无须访问每个平台。使用其他可访问来源，记录访问限制及影响。
读取并对照关键原文，给出精确陈述和证明位置。
摘要或文字相似度不能替代数学对照。

反对意见须提供具体来源、可能的等价关系或推导，或影响判断的具体检索缺口。
有具体线索即可启动定向核查，无须先有完整的重合证明。
确认重合需要精确来源和覆盖证据。
原创性 worker 提供新论证，其固定 verifier 审核。

verifier 的建议交回 worker。未审核的 verifier 推导不能作为已准入依据。
可独立使用的新等价结果或归约仍须通过 `DERIVED`。原创性不是第三种准入渠道。
