# 数学研究规则

## 1. 范围与术语

本规则适用于采用本文件的项目中的数学研究。
配套研究技能为可选项。
如有配套研究技能，使用其中的详细流程。

| 术语 | 含义 |
| --- | --- |
| 目标（Target） | 精确的数学问题及版本。 |
| 路线（Route） | 1 种证明方法或反例构造方法。 |
| 配对（Pair） | 针对同一轮内 1 条路线的固定 worker 与固定 verifier。 |
| 轮次（Round） | 目标和配对上限明确的一段研究工作。 |
| 会话（Session） | 1 次 Codex 对话或执行上下文。 |
| 事实（Fact） | 包含条件和来源的完整数学记录。 |
| 准入（Admission） | 通过 2 条允许渠道之一接纳事实。 |
| 事实图（Fact graph） | 事实、版本、依赖关系和可用性。 |
| 正式提交（Submission） | worker 固定内容后正式送审的工作。 |
| 审核（Review） | 固定 verifier 对精确提交版本的判决。 |
| 交接（Handoff） | 说明轮次结果并支持后续续做的记录。 |

准入表示责任角色已按本流程接纳事实。

## 2. 角色

使用 Codex 子代理承担 researcher、worker 和 verifier 职责。
controller 负责协调。
向每个子代理提供角色、允许输入、任务和输出路径。

代理容量不足以并行工作时，按顺序执行任务。
必要角色无法运行时，报告限制。
禁止将证明或审核职责并入 controller 角色。
角色指令不会建立沙箱隔离。

| 角色 | 允许的工作 | 边界 |
| --- | --- | --- |
| controller | 阅读原始材料。规划不同路线。分配配对。管理预算、文件、信息和恢复。依据准入判决记录结果。 | 禁止证明命题、裁决数学正确性、修补证明缺口或通过新推导组合成果。 |
| researcher | 检索前人工作。阅读来源。提取完整结果。接纳忠实提取的文献事实。记录记号变换和来源限制。 | 禁止产生新证明或将新推导写成文献提取。 |
| worker | 推进 1 条路线。编写证明或反例。执行必要计算。正式提交工作并修复已报告的缺陷。 | 禁止自我批准或将候选成果加入已接纳事实。 |
| verifier | 仅审核固定 worker。检查正确性和精确目标覆盖范围。明确接纳成果或要求返工。 | 禁止审核其他 worker。禁止暗中补全证明后接纳未修改的提交。 |

在同一轮的全部返工期间，保持 worker 与 verifier 固定配对。
禁止为取得不同判决而更换 verifier。
代理实例丢失时，新实例可以按原任务和审核历史接续原角色。
保持配对身份和预算不变。
审核产生新研究成果时，将成果交回 worker，纳入明确版本的正式提交。

## 3. 数学边界

在目标记录中保留原题、定义、量词、参数范围、假设和所求结论。
单独记录附加研究请求，不与目标状态混合。
例如：新证明或更优的界。
用户修改目标时，保留原版本并记录修改。
路线增加条件或弱化结论时，另记命题。
禁止用新命题替换原始目标。

目标等价性需要证明时，将证明任务交给配对。

仅使用这 2 条准入渠道：

- `LITERATURE`：researcher 接纳忠实提取的内容，保留完整条件和精确来源位置。
- `DERIVED`：固定 verifier 明确接纳固定 worker 某次正式提交中的命题。

禁止将重证明或第 2 位 verifier 设为每条文献结果的准入条件。
区分定义、局部假设、已接纳定理、猜想和实验观察的逻辑类型。
存在性、唯一性或等价性主张必须有依据。
这些主张附在定义中时，也必须有依据。

引用既有数学结果时，worker 必须使用事实图中允许且可用的事实。
写明项目的基础逻辑规则和数学约定。
无须为每个算术步骤建立事实节点。
向 researcher 请求缺失的外部结果。
禁止将模型记忆、其他 worker 的草稿或路线设想作为已接纳前提。

待审证明可以包含完整的局部推导。
其他任务将局部成果作为既有事实使用前，先取得准入。

配对之间可以传递已接纳事实、来源请求、路线范围和行政进度。
未准入证明仅在所属配对和 controller 的行政管理范围内流转。
其他路线需要候选命题时，将命题作为待证目标发送。

组合已接纳成果需要新推导时，在轮次预算内分配配对。
在同一轮内，原配对可以在原路线和剩余提交预算内完成组合。
采用新的核心方法时，使用新配对。
总结不能代替组合证明。
用 `L ⇒ T` 证明 `T` 前，先提供 `L` 的已接纳支持。

在每次正式提交中记录精确事实版本。
事实输入改变时，明确记录新依赖。
禁止因旧快照含有某前提，就继续使用已知失效或有争议的前提。
禁止将循环证明依赖作为依据。
相互蕴含或共同归纳必须有明确证明。

证明有缺陷不表示命题为假。
区分命题和各项支持来源。
停止使用受影响的支持。
依赖成果缺少已接纳且适用的支持时，停止使用依赖成果。

已有记录确立适用性时，保留同一精确命题的其他已接纳支持。
将新数学判断交给责任 researcher 或配对。
保留每次修改的历史和原因。

计算不会自动证明一般命题。
证明依赖计算时，worker 必须论证覆盖性、精确性和充分性。
verifier 必须检查这项论证。
程序运行无错误或 PDF 编译成功不等于数学审核通过。

## 4. 预算与结果口径

用户未另行指定数值或结果规则时，使用下列默认值。
在 `ROUND.yaml` 中记录采用的口径。
按用户的明确指示修改口径。

| 项目 | 默认值 |
| --- | --- |
| 配对上限 | 每轮 4 对。轮次也可以指定为 3 对。 |
| 配对计数 | 本轮实际开展证明或审核的全部不同配对。 |
| 提交上限 | 首次提交 1 次，返工 3 次。每对最多 4 次。 |
| 提交历史 | 同一轮内，次数跨暂停和会话累计。新轮使用新配对并重新计数。 |
| 结果范围 | 精确目标截至本轮的累计进展。 |
| 新成果 | 本项目推导并接纳的、与目标有关的成果。世界范围的原创性另作主张。 |
| 部分成果 | 已接纳的附条件结果、实质性引理、较弱结论、部分参数结果或严格归约。 |

新探索、组合证明和独立引理任务占用本轮名额。
同一配对内返工和续做不另占名额。
文献工作、路线规划、读取既有事实和行政恢复不占配对名额。
配对结束或失败后不退还名额。

配对上限不是代理并发上限。
可以保留 1 个名额供后续任务使用。保留的名额无须用完。

worker 将固定版本正式送审时，计为 1 次正式提交。
修改草稿、重复传送、继续审核或仅调整排版不增加次数。
修改命题、假设、依赖或证明内容后，再次正式提交必须使用新版本。
同一轮内，禁止通过改名、新会话或替换代理重置次数。

续做消耗剩余预算前，恢复未知计数。
超过配对提交上限前，取得用户明确约定。保留配对历史。
新会话本身不会产生新轮次预算。
自动跨轮工作前，取得用户约定。

仅使用这 4 个数学结果值：

| 值 | 必要依据 |
| --- | --- |
| `PROVED` | 已接纳证明或精确对应的文献结果确立原始目标。 |
| `DISPROVED` | 已接纳的严格证伪适用于原始目标。反例满足原假设，并违反原结论。 |
| `PARTIALLY_RESOLVED` | 原始目标仍未解决。已接纳的项目成果符合部分成果规则。 |
| `UNRESOLVED` | 原始目标仍未解决。没有已接纳的项目成果符合部分成果规则。 |

单独列出本轮新增成果。
单独报告附加研究请求的完成程度。
证明失败、预算耗尽或搜索未找到反例，均不能确立证明或证伪。

写明附加条件。
结果未知不等于 `UNRESOLVED`。
结果未知时，省略 `result_status` 字段。记录缺失的依据。

将 `MISSING_SPECIFICATION` 和 `LITERATURE_CONFLICT` 写入 `issues`。
事项标记与数学结果分开。
证明步骤缺失不等于原题说明缺失。
仅停止依赖缺失信息或争议事实的任务。
controller 禁止补造题意或在数学冲突中自行选边。
明确报告目标假设之间的矛盾。

## 5. 记录

仅 controller 更新共享控制文件和发布事实图快照。
照录准入判决，保持数学内容不变。
保持正式提交、已完成审核和已发布快照的原内容。
修改时，新增版本或明确的更正记录。

持久记录使用稳定标识和项目根目录相对路径。
区分提交版本、事实版本和图版本。
再次引用历史事实前，通过 `CURRENT.yaml` 检查当前可用性。
检查点服从实际正式记录。

所有持久路径以项目根目录为基准。
日期使用用户所在时区。默认时区为 `Asia/Shanghai`。
轮次命名为 `rounds/yyyy_mm_dd_roundNNN/`。
使用创建日期，在整个项目内连续编号。

到达必要研究阶段时才创建文件。空目录可建可不建。
禁止创建空证明、空审核、空 PDF 或尚未发生的提交版本。

在项目根目录或轮次根目录保留以下记录：

| 位置 | 记录 | 必要内容 |
| --- | --- | --- |
| 项目 | `README.md` | 目的、规则位置、日期与路径约定、口径位置。阅读顺序、补充论文规则、暂缓功能。禁止另建进展台账。 |
| 项目 | `CURRENT.yaml` | `project_id`、`current_round`、`current_fact_head`、`latest_handoff`。路径目标可用后，才能填写路径。 |
| 轮次 | `PROBLEM.md` | 第 3 节规定的完整目标、标识、修订版本、附加请求、不确定内容和修改。旧目标版本保存在不同路径。 |
| 轮次 | `ROUND.yaml` | 轮次、创建时间、前轮、目标版本与路径、输入图。用户指示、采用口径、预算、已开始工作的配对。 |
| 轮次 | `ROUTES.md` | 路线标识、核心方法、差异、已接纳输入、证明缺口、配对分配、结果和停止原因。 |
| 轮次 | `CHECKPOINT.yaml` | 最近完整图、正式提交、已完成审核、待完成审核。已接纳但尚未登记的事实、未完成请求、工作路径、下一步动作。 |

预算字段使用 `max_pairs`、`max_formal_submissions_per_pair` 和 `started_pair_ids`。
依据当前轮次的正式记录计算次数。禁止维护第 2 套独立预算台账。

每轮保留以下 9 类目录的职责：

| 目录 | 记录与用途 |
| --- | --- |
| `code/` | 配对工作和 `PAIR_ID/runs/RUN_ID/` 中的固定计算证据。`RUN.yaml` 记录命令、环境、依赖、输入、输出、随机种子和限制。 |
| `audit/` | `EVENTS.jsonl` 记录重要事件。`recovery/RECOVERY_NNN.md` 保存详细恢复记录。`handoffs/HNNN/` 保存已替换的交接。 |
| `fact_graph/` | `snapshots/` 保存完整累计快照。`HEAD.yaml` 包含 `graph_id` 和 `snapshot_path`。 |
| `src/` | 可选论文源码：`main.tex`、`references.bib` 和 `CLAIMS.yaml`。将命题对应到精确事实和证明位置。 |
| `out/` | 可选 `paper.pdf` 和 `BUILD.yaml`。记录固定源码路径、图版本、编译时间、命令和工具。 |
| `research_papers/` | `RESEARCH.md` 记录发现、缺口、准入事实和检索限制。`SOURCES.yaml` 记录来源元数据。`pdf/` 保存可获取的来源 PDF。 |
| `pairs/` | 每对使用独立目录：`TASK.md`、`drafts/`、`submissions/vNN/SUBMISSION.md` 和 `reviews/vNN/REVIEW.md`。 |
| `final/` | 第 6 节规定的 5 个交接文件。 |
| `temp/` | 临时材料。清理前，将必要证据移到稳定路径。 |

每条来源记录包含标识、标题、作者、年份、版本、链接或文献标识。
同时包含获取时间和访问限制。
记录可用文件路径。
文献事实需记录精确陈述位置和记号变换。
对已证命题，记录证明位置或引用的证明来源。

阅读来源正文和上下文。仅有检索片段不足以作为依据。
记号变换时，保持数学含义不变。
变换需要推导时，将任务交给配对。

在 `TASK.md` 中记录配对、固定角色、路线、目标和范围。
同时记录允许的事实版本、方法、预期产物、约束和提交上限。

每次正式提交记录配对、worker、版本、送审时间和目标版本。
同时记录编号命题、假设、依赖和完整论证。
包含计算、修改、未完成工作和对前次缺陷的回应。

每次审核记录 verifier、精确提交及路径、范围、判决和原因。
同时记录准入命题、依赖和剩余义务。
审核判决使用 `ACCEPT`、`REWORK` 或 `INCOMPLETE`。
这些判决不是轮次结果。
独立局部成果仅在依据完整且范围明确时准入。
其他命题返工不取消这项准入。

每条事实记录包含标识、修订版本、逻辑类型和完整陈述。
同时包含定义、条件、作用域和精确依赖。
包含准入渠道、来源位置或提交命题、准入判决和责任角色。
同时包含可用性和更正历史。
同一命题有不同的已接纳支持时，分别保留支持记录。

准入或修改已接纳事实、支持、可用性后，保存新的完整图快照。
随后更新 `HEAD.yaml` 和 `CURRENT.yaml`。
重要事件需记录时间、责任角色、对象标识和证据路径。
正式送审、完成审核、发布图或计划中断后，更新检查点。
原始判决保留在其来源记录中。

可以创建项目级空目录 `additional_papers/`。
保持已有用户文件不变。
禁止例行列出、扫描、读取或监测这个目录。
用户在提示词中提及补充论文时，仅读取请求范围内的材料。
researcher 记录实际使用，并遵循准入规则。
清理临时文件时，禁止删除补充论文。

保留必要的角色检查和数学计算代码。

## 6. 研究顺序与交接

新轮只接收用户要求、`CURRENT.yaml`、当前事实图和最近的 `final/` 总结。
开始新轮时，禁止读取旧配对目录、提交、审核、草稿或检查点。
补记此前暂停或续做中断轮次时，使用第 7 节。
补记暂停本身不要求恢复执行记录。
建立新轮前，完成第 7 节规定的必要确认。

1. 阅读目标、用户限制和可取得的 `CURRENT.yaml`。
2. 阅读最近交接和任务所需的完整事实。
3. 符合恢复条件时，改用第 7 节，不执行下列新轮步骤。
4. 记录新轮次、精确目标、采用口径、新预算和完整初始事实快照。
5. 分配文献调查任务，并记录准入结果。
6. 在配对上限内选择不同的核心路线。
7. 向各 worker 提供任务、允许的事实和固定 verifier。
8. 各配对开始证明或审核时，登记配对。
9. 在提交上限内将固定工作送审。
10. 发布准入事实，保留精确范围和依赖。

每个新轮将 `started_pair_ids` 设为 `[]`。
创建新的配对标识、角色分配和 `TASK.md` 记录。
每对的正式提交版本从 `v01` 开始。
禁止将旧配对、待完成审核或已用提交次数转入新轮。
继承事实时，保留原标识、修订版本和来源引用。

文献直接解决目标时，记录精确目标对应关系。
这项结果无须证明配对。
单独保留附加研究请求。

目标解决、任务完成、预算耗尽或达到约定边界时，结束轮次。
原题说明缺失或文献冲突也可以结束受影响工作，并保留明确说明。
未发生中断的收尾在 `final/` 中使用这 5 个文件：

| 文件 | 必要内容 |
| --- | --- |
| `START_HERE.md` | 目标、精确结果、关键事实、本轮变化、路线结果、限制、下一步动作和阅读路径。 |
| `RESULT.yaml` | 结束声明、结果和依据、范围、新成果、剩余义务、事项、源图、记录时间和交接完整性。 |
| `PROBLEM.md` | 实际采用的目标版本副本，包含标识、修订版本和源路径。 |
| `FACTS.json` | 完整源快照的原样副本，包含图标识和事实可用性。 |
| `FRONTIER.md` | 未完成证明义务、路线结果、已接纳部分成果与条件。失败步骤、来源请求、事项和候选目标。 |

1. 汇总正式结果和未完成任务。
2. 发布尚未入图的已接纳事实。
3. 依据完整图和正式记录准备交接。
4. 对照来源检查目标版本、事实版本、判决、次数和证据路径。
5. 交接齐备后，在 `final/RESULT.yaml` 发布实际结束声明。
6. 在 `CURRENT.yaml` 中更新最近交接路径。
7. 清理临时文件前，保留必要证据。

在 `RESULT.yaml` 中使用 `record_type: ROUND_END` 和 `round_id`。
同时记录目标标识、修订版本和 `recorded_at`。
包含已知的 `result_status`、`result_scope`、`basis_fact_ids` 和 `new_results_this_round`。
同时包含 `scope_note`、`remaining_obligations`、`source_graph_id`、`issues`、`handoff_complete` 和 `missing_files`。

以明确的文献对应或 verifier 判决作为依据。
交接必须支持开始新轮，无须读取旧执行记录或完整对话历史。
未解决设想保留为候选目标。仅已接纳事实可作为既有前提。

证据可以保留在 `final/` 之外的实际路径。
